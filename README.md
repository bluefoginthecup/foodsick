# 나두아파

음식점 이름과 정확한 위치를 공개하지 않고, 지역별 위장관 증상 신고 증가를 살펴보는 모바일 우선 PWA MVP다. 특정 업소의 식중독 발생을 판정하거나 안전도를 평가하지 않는다.

## 현재 구현 범위

- 비식별 행정구역 지도와 최근 1년 날짜·음식 유형 필터
- 선택 지역 기준 시청·구청·보건소 연락처를 카카오 Local API로 조회하고 대학병원·응급실·내과 검색 제공
- 기관 연락처는 서버에서 6시간 캐시 후 다시 조회하며, 식품위생 담당부서는 검색 결과가 확인될 때만 표시
- 카카오 로그인 연동 경계와 외부 키 없는 체험 로그인
- 식사, 증상, 동행자, 의료정보 다단계 신고 설문
- 잠복시간 계산, 음식점 내부 장소 ID 매칭
- 동일 사용자·음식점·식사일 중복 방지와 기존 신고 수정
- 독립 신고와 동행 증상자 분리 집계
- 규칙 기반 클러스터와 동→구→시 재식별 방지 관문
- 관리자 신고·클러스터·감사기록 화면
- Firebase Security Rules 초안과 PWA 민감 경로 캐시 차단
- App Check 기반 Cloud Functions 신고 생성·수정 API
- Firestore 원자적 중복 방지, 사용자별 요청 제한, 관리자 감사기록
- Firebase 웹 클라이언트와 서울 리전 Callable Functions 연결 어댑터

Firebase 프로젝트 `foodsick-signal-map-kr`의 운영 설정은 `NEXT_PUBLIC_AUTH_MODE=firebase`다. 카카오 로그인과 신고 저장을 사용하며, 공개 지도는 실제 서버 집계를 조회한다. App Check 클라이언트는 연결되어 있지만 기존 Callable Functions의 서버 강제 검증은 별도 운영 과제로 남아 있다.

## 실제 신고의 공개 반영

- `syncReportSignals`가 신고 생성·수정·삭제·상태 변경을 감지하고 이전/새 음식점 양쪽을 재집계한다.
- 같은 장소 ID와 음식 유형, 72시간 식사 구간, 서로 다른 계정 3명 이상, 위장관 증상을 요구한다. 동행자는 독립 신고로 세지 않는다.
- 카카오 장소 ID를 다시 확인하고 행정구역 안의 같은 음식 유형 업소를 최소 3곳 확인한 뒤 동→구→시로 공개 범위를 결정한다. 자유 입력 장소·기타/배달음식처럼 확인이 불충분한 경우 공개하지 않는다.
- 공개 API는 지역·음식 유형·날짜·집계 수치만 허용한다. 음식점/사용자/신고 ID와 좌표는 반환하지 않고, 세부 수치 3 미만은 비공개로 유지한다.
- 변경 도중 오래된 집계가 덮어쓰지 않도록 트랜잭션 안에서 원본 버전을 재확인한다. 같은 이벤트가 반복되어도 공개 문서는 중복 생성되지 않는다.
- `reconcilePublicSignals`는 6시간마다 기존 자료 및 누락 이벤트를 재확인한다. 한 번에 음식점 100개, 최대 450초를 처리하고 다음 실행에서 이어간다. 공개 확인 근거는 24시간 후 만료되며 검증에 실패한 신호는 숨긴다.
- 한 음식점의 최근 1년 신고가 2,000건 또는 후보가 150개를 넘으면 부분 집계 대신 공개를 보류하고 `signalPublicationState`에 검토 상태를 남긴다.
- 공개 지도는 최근 365일을 조회하고, 보이는 탭에서 1분마다 갱신한다. 조회 오류와 공개 신호 없음은 별도로 표시한다.
- 신고 지역 목록은 지도와 같은 `admdongkor` 20260701 자료를 압축한 `public/administrative-regions.json`이다. 갱신은 `node scripts/build-region-options.mjs`로 수행한다.

브랜드는 **나두아파**이며 기존 Firebase 주소는 유지한다. 공유 이미지는 내장 이미지 편집 도구로 기존 이미지의 ‘아파요 지도’만 ‘나두아파’로 교체했다. 최종 프롬프트: “Replace ONLY the large Korean brand text '아파요 지도' with exact text '나두아파'. Keep the smaller line '나만 아픈 걸까?' and all other artwork unchanged.” 결과 파일은 `public/og-nadoapa.png`다.

## 다국어 화면

- 한국어, 영어, 중국어 간체, 일본어, 베트남어를 지원한다. 첫 요청의 브라우저 언어를 적용하고 지원하지 않는 언어는 영어로 표시한다. 상단 언어 선택은 페이지 이동 후에도 쿠키와 로컬 저장소로 유지한다.
- `app/i18n`의 정적 번역 파일을 React 렌더링에 적용한다. 브라우저 DOM을 사후 치환하지 않으며 실행 중 번역 서비스 호출도 없다. 증상·음식 유형 등의 저장 값과 API 계약은 한국어/기존 코드 그대로 유지한다. 사용자 자유 입력, 이름, 음식점·주소·메모는 원문을 유지한다.
- 공개 UI 문구로 초기 번역을 생성한 뒤 `reviewed.json`에서 브랜드, 주요 증상, 동의문과 핵심 안내의 번역을 보정했다. 번역 수정은 언어별 JSON 또는 검토 파일에서 관리한다.
- 새 문구 추가 시 `node scripts/extract-i18n.mjs`로 목록을 갱신하고 네 언어의 번역을 채운 뒤 `node scripts/review-i18n.mjs`를 실행한다. `tests/i18n.test.mjs`와 서버 렌더링 테스트는 언어 선택, 번역 누락, 치환 변수, 기존 신고 값 보존을 확인한다.

## 실행과 검증

Node.js 22.13 이상이 필요하다.

```bash
npm install
npm run dev
npm test
npm run lint
npm run functions:build
npm run functions:test
```

환경변수는 `.env.example`을 참고한다. 실제 비밀키는 저장소에 커밋하지 않는다.

## 공개 금지 경계

공개 데이터에는 음식점 상호·주소·정확 좌표·내부 음식점 ID·신고 ID·사용자 ID를 포함하지 않는다. 원본 신고와 공개 집계는 별도 컬렉션 및 별도 API 경계로 운영한다.

## 관리자 테스트 회원

관리자 검토실의 **테스트 회원** 메뉴에서 시험별 1~100명을 생성한다. 카카오 계정이나 공용 비밀번호 없이 관리자 전용 `manageTestMembers`가 일반 회원 권한의 Firebase custom token을 발급한다. 일반 회원을 대상으로 발급할 수 없으며, 종료된 시험과 탈퇴 중인 계정은 차단한다.

- **회원으로 접속**: 별도 창의 Firebase 앱과 탭별 세션 저장소를 사용한다. 관리자 로그인은 유지하며, 토큰은 같은 출처의 지정된 창에만 전달하고 URL에는 넣지 않는다. 테스트 창에서는 기존 신고·내 신고 화면을 그대로 사용한다.
- **자동 신고**: 각 회원으로 메모리 내 로그인한 뒤 기존 submitReport/updateReport/deleteMyReport API를 호출한다. 100명의 기본 시나리오는 30명 그룹 신고, 40명 개별 신고, 20명 동행자 정보, 10명 중복·수정·삭제다. 화면을 닫으면 다음 회원부터 중단하며 다시 실행할 수 있다. 실행 결과는 현재 화면에 표시된다.
- 자동 신고는 시험별 가상 음식점과 고정 날짜를 사용한다. 기존 공개 검증 절차에서 장소 확인을 통과하지 않으므로 공개 지도에 게시되지 않는다. 실제 장소를 직접 선택한 수동 신고에는 같은 공개 기준이 적용된다. 카카오 인증 자체와 실제 장소의 공개 확인 성공 여부는 별도 시험 대상이다.
- **시험 종료·전체 파기**: 회원을 원자적으로 잠근 뒤 기존 재시도 가능한 탈퇴 작업을 생성한다. 인증 계정, 회원, 신고, 동행자, 중복 키, 요청 제한, 활동 및 테스트 회원의 관리자 검토 기록을 삭제한다. 보고서 삭제 이벤트가 공개 집계를 재계산한다. 새로고침으로 남은 회원 수를 확인하며, 모두 삭제되면 자동 생성된 가상 음식점과 장소 확인 캐시도 정리한다. 실제 음식점의 공유 기준 정보는 삭제하지 않는다. 시험 번호·개수·종료 상태 등 운영 메타데이터는 남긴다. 백업과 플랫폼 로그는 별도 보존 정책을 따른다.

운영 사이트에 기능을 배포하는 것만으로 테스트 회원이나 신고를 자동 생성하지 않는다. 관리자 메뉴에서 생성·실행한다.

## 논문·참고자료 게시판

`/resources`에서 자료를 유형별로 읽고 검색한다. 공개 조회는 로그인이 필요 없으며 서버에서 `approved` 상태만 반환한다. 작성자 UID, 검토 메모, 내부 버전은 공개 응답에 포함하지 않는다. 검색·유형·검토 상태 필터는 현재 불러온 글에 적용하며, 다음 30개를 이어서 불러올 수 있다.

- 회원: 글 작성, 내 글 수정·삭제, 승인 상태와 반려 사유 확인. 신규 작성과 수정은 항상 `pending`으로 저장되어 재승인 전까지 공개되지 않는다.
- 관리자: 즉시 게시, 모든 글 수정·삭제, 승인·반려 및 공개 취소. 관리자 검토실의 **자료실 승인·관리** 또는 자료실에서 관리한다. 반려 시 사유를 입력한다.
- 확인한 논문·공식 자료 7개는 관리자 작성 폼의 추천 초안이다. 자동으로 게시하지 않으며 관리자가 내용을 확인하고 저장·공개한다.
- `resourcePosts`는 클라이언트의 직접 읽기·쓰기를 금지하고 Callable Functions에서 계정·소유권·관리자 권한을 검사한다. 변경·검토·삭제는 버전을 확인하는 트랜잭션으로 충돌을 차단한다. 회원 신규 글은 UTC 일자 기준 하루 20건으로 제한한다.
- 탈퇴 시 작성한 게시글도 삭제한다. 기존 화면에 이미 내려받은 글은 새로 조회할 때 갱신된다.
- 운영 반영에는 웹 앱, `listResourcePosts`, `saveResourcePost`, `reviewResourcePost`, `deleteResourcePost`, 변경된 `processAccountWithdrawal` 함수 및 Firestore 인덱스 배포가 필요하다. 체험 모드는 실제 게시판에 쓰지 않는다.

## 관리자 신고 통계·엑셀 (1차)

관리자 메뉴의 **신고 통계·엑셀**에서 전체 자료를 조회한 뒤 양식(증상/CDC/전체), 회원(실제/테스트/확인 불가/전체), 신고일·식사일 기간, 지역·음식점 이름, 증상, 검토 상태로 필터링한다. 기본은 실제 회원의 증상 신고이며, 회원 정보가 없는 자료를 실제 회원으로 추정하지 않는다. 신고일은 한국 시간 기준이다.

- 신고 건수·서로 다른 신고자 수·동행 증상자 합계·병원 방문·입원 건수, 날짜·지역·음식 유형·증상·음식점별 표와 막대를 제공한다. 항목을 누르면 해당 신고의 전체 답변, 동행자, CDC 식사 기록으로 이어진다.
- CDC 동행 증상자 수는 본인 포함 응답에서 1을 빼며, 미응답을 0으로 추정하지 않는다. CDC 자유 입력 장소는 기존 음식점 ID와 자동 매칭하지 않는다. 두 양식 간 같은 사건·동행자를 자동 중복 제거하지 않으며 증상은 복수 선택이다.
- 조회는 서버에서 관리자 권한을 검사한 후 문서 ID 순서로 모든 페이지를 읽는다. 조회 중 변경될 수 있으므로 고정 시점 스냅샷이 아니다. 전체 10,000건 또는 UTF-8 JSON 40MB 초과 시 부분 통계나 부분 다운로드를 제공하지 않고 오류를 표시한다.
- 엑셀은 현재 필터와 상세 항목 선택을 그대로 적용한다. 요약 통계, 증상 신고, 동행자, CDC 신고, CDC 식사 기록의 5개 시트로 생성하며 원본 자유 입력은 수식으로 실행되지 않는 문자열로 저장한다. ExcelJS는 다운로드 때 별도 로드한다.
- 다운로드 전 서버가 관리자·요청 시각·조회 조건·요청 건수·자료 조회 완료 시각을 adminAuditLogs에 기록한다. 브라우저의 파일 저장 완료 여부를 서버에서 보장하는 기록은 아니다. 원본 답변은 감사 로그에 복제하지 않는다.


### 동일 집계 경로·관리자 업소 상세·공개 메뉴

- 실제 및 테스트 공개 판단은 `evaluateSignals`를 공유한다. 실제 발행은 서버 회원 정보를 조회해 테스트·탈퇴 중·확인 불가 계정을 제외한다. 시험은 선택한 활성 묶음에 한정한다.
- 새 시험은 scenarioVersion 2의 가상 장소 증거를 사용한다. 외부 장소 조회만 대체하며 3명/72시간/증상/지역 확대/세부수치 숨김은 실제 코드다. 기존 시험은 원본을 보존하고 장소 미확인으로 남긴다.
- 100명 자동 실행 후 10명은 중복·수정·삭제를 시험한다. 초기 예상은 남은 신고90건/후보14개/공개신호9개이며 서버 결과와 비교한다. 외부 검색 API 자체와 대규모 부하는 별도 시험이다.
- 홈의 관리자 자료 조회 후 지역→업소→개별 신고를 확인한다. 원본 집계와 공개 집계는 중복 제거 및 공개 조건 때문에 다를 수 있다. CDC는 구조화된 장소 식별이 없어 이번 지도 집계 대상에 포함하지 않는다.
- 공개 메뉴는 정해진 일반 메뉴 목록만 허용한다. 기존 원문은 구분자로 나눈 항목의 정확한 일치만 자동 연결하며 임의 추론하지 않는다. 관리자 검토 메뉴가 우선하고 빈 배열은 비공개 확정이다. 사용자 수정은 검토 결과를 초기화한다.
- 공개 신호 안에서 같은 표준 메뉴를 선택한 독립 신고자3명 이상일 때만 메뉴명(개별 건수 없음)을 내보낸다. 원문·업소명·신고자ID는 공개 응답에서 제외된다. 표준화는 재식별 가능성을 완전히 없애는 보장이 아니다.
- schemaVersion3 이전 공개 신호는 새 발행기로 재집계되어야 조회된다. 정기 재집계 또는 관리자 업소 상세 조회로 재발행한다. 관리자 조회는 전체1만건/40MB, 업소 평가2000건까지이며 한도 초과는 부분 통계로 표시하지 않는다.


### 통합 신고·공개 지도 (현재 운영 정책)

사용자 요청에 따라 실제·테스트 회원의 신고를 같은 업소 기준으로 합산한다. 지도 전환과 시험 묶음 필터는 제거했다. 회원의 테스트 표시는 일괄 탈퇴·파기 관리에만 쓰며 집계에서 제외하지 않는다. 등록된 가상 음식점은 서버가 확인한 시험 묶음의 장소 증거를 사용해 일반 publicSignals에 발행한다. 가상 메뉴 원문은 공개하지 않고 기존 표준 메뉴 규칙을 적용한다. 기존 수동 시험 장소도 등록 여부 확인 후 집계한다. 회원 파기 과정의 reports 삭제 트리거가 같은 업소를 재집계하여 신호를 갱신·제거한다. 통계 기본 조회는 모든 회원이다. 이 정책이 위의 실제·테스트 집계 분리 설명을 대체한다.

공개용 메뉴 선택·검토 UI는 제거했다. 일반 지도에는 신고의 음식 유형만 표시하고 메뉴 원문은 관리자 상세에 남긴다. 공개 API는 과거에 저장된 공개 메뉴도 반환하지 않는다.

관리자 신고 통계: 상세 신고의 체크박스와 현재 조건 전체 선택(페이지 전체)을 지원합니다. 선택한 신고 삭제는 건수 확인 후 25건씩 처리하며, 증상·CDC 원본과 연결 동행자/중복키를 삭제하고 기존 트리거로 지도를 재집계합니다. 관리자 인증·조회 후 수정 검사·부분 완료 안내·감사기록을 적용합니다. 회원 계정은 삭제하지 않습니다.

공개 지도 의료 표시: 메뉴는 선택한 음식 유형만 표시합니다. 동행 증상자·통원·입원은 0을 그대로 공개하고 1~2는 소수 인원, 3 이상은 숫자로 표시합니다. 통원은 병원 방문+입원 아님, 입원은 입원 응답 기준으로 중복 없이 집계하며, 과거 입원 여부 미응답은 미확인으로 남깁니다. 지역 합계는 확인된 수치와 소수/미확인 포함을 함께 표시합니다.
